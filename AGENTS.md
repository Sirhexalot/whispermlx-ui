# Repository notes

- The macOS app is generated from `project.yml` with XcodeGen. Build via `./build.sh Debug` (or `./build.sh Release`): it regenerates `WhisperMLXUI.xcodeproj`, builds with derived data outside the iCloud-synced workspace, copies the app to `dist/<configuration>/`, and verifies the staged signature. Do not assume `swift build` packages the runnable app or its CLI/FFmpeg resources.
- The `project.yml` post-build script embeds `bin/whispermlx`, `bin/whispermlx_runtime.py`, and executable `bin/ffmpeg`; if FFmpeg is absent, run `scripts/build-bundled-ffmpeg.sh` before the app build. `bin/ffmpeg` is ignored by Git. The authoritative translations are `Sources/WhisperMLXUI/*.xcstrings`; legacy `Resources/*.strings` are deliberately excluded to avoid duplicate tables.
- Runtime path: `WhisperMLXUIApp.swift` creates `TranscriptionController`; it launches the bundled `bin/whispermlx` process. That shell wrapper chooses a Python interpreter (override with `WHISPERMLX_PYTHON`; otherwise prefer the managed venv at `~/.local/share/whispermlx-ui/venv/bin/python`) and invokes `bin/whispermlx_runtime.py`, which patches WhisperMLX in memory for raw-transcript checkpoints and isolated CPU alignment workers. Do not edit installed site-packages to change this behavior.
- Python tests require NumPy; the system `python3` may not have it. Use the managed runtime: `~/.local/share/whispermlx-ui/venv/bin/python -m unittest discover -s tests -p 'test_*.py'`. For one test, add `-k test_raw_cache_skips_model_loading_and_invalidates_changed_source`.
- Outputs and resumable checkpoints are written beside the source recording in `<stem>.transkript/`; alignment block caches are intermediate, not finished transcripts. Diarization can use a local model or a Hugging Face token stored in Keychain; never commit tokens or `.env` contents.
- For a signed/notarized release use `scripts/create-release.sh Release`, not `package-release.sh` (which only zips the development-signed build). The release script clears project build caches before rebuilding but preserves prior `dist` releases and Sparkle files; it requires `APPLE_DEVELOPER_IDENTITY` and `APPLE_NOTARY_PROFILE`. Publishing to GitHub and updating the Sparkle feed are separate steps; do not claim the release is published just because the ZIP exists.
