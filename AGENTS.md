# Repository notes

- The macOS app is generated from `project.yml` with XcodeGen. Build via `./build.sh Debug` (or `./build.sh Release`): it regenerates `WhisperMLXUI.xcodeproj`, builds with derived data outside the iCloud-synced workspace, copies the app to `dist/<configuration>/`, and verifies the staged signature. Do not assume `swift build` packages the runnable app or its CLI/FFmpeg resources.
- The `project.yml` post-build script embeds `bin/whispermlx`, `bin/whispermlx_runtime.py`, and executable `bin/ffmpeg`; if FFmpeg is absent, run `scripts/build-bundled-ffmpeg.sh` before the app build. `bin/ffmpeg` is ignored by Git. The authoritative translations are `Sources/WhisperMLXUI/*.xcstrings`; legacy `Resources/*.strings` are deliberately excluded to avoid duplicate tables.
- Runtime path: `WhisperMLXUIApp.swift` creates `TranscriptionController`; it launches the bundled `bin/whispermlx` process. First-run setup (`RuntimeSetup.swift` -> `bin/setup-runtime`) installs pinned Python 3.13.14 / WhisperMLX 3.14.0 / MLX 0.32.3 under `~/.local/share/whispermlx-ui/runtime`. The wrapper prefers that runtime, with `WHISPERMLX_PYTHON` for tests; it invokes `bin/whispermlx_runtime.py` for checkpoints and CPU alignment. Dependency hashes live in `runtime-requirements.txt` (regenerate from `runtime-requirements.in` with uv). Never edit installed site-packages.
- Python tests require NumPy; the system `python3` may not have it. Use the managed runtime: `~/.local/share/whispermlx-ui/venv/bin/python -m unittest discover -s tests -p 'test_*.py'`. For one test, add `-k test_raw_cache_skips_model_loading_and_invalidates_changed_source`.
- Outputs and resumable checkpoints are written beside the source recording in `<stem>.transkript/`; alignment block caches are intermediate, not finished transcripts. Diarization can use a local model or a Hugging Face token stored in Keychain; never commit tokens or `.env` contents.
- For a signed/notarized release use `scripts/create-release.sh Release`, not `package-release.sh` (which only zips the development-signed build). The release script clears project build caches and `dist/Debug` before rebuilding, but preserves `dist/Release` and Sparkle files; it requires `APPLE_DEVELOPER_IDENTITY` and `APPLE_NOTARY_PROFILE`. Publishing to GitHub and updating the Sparkle feed are separate steps; do not claim the release is published just because the ZIP exists.
- `build.sh` bundles a native `uv` executable via `scripts/build-bundled-uv.sh` (requires local uv); FFmpeg remains bundled. Test the setup script with a temporary `HOME` rather than overwriting the user's installed runtime; an app build alone does not verify first-run setup or notarization of nested uv.
